2.1 Quick presentation
Sigmalink is a client server application. The server part must be installed on a dedicated machine.
Clients communicate with server using HTTP protocol through a simple internet browser.
KSeries and PI machines communicate with the Sigmalink machine by the same way, but for
performance reason, you can share directory between inspection machines and Sigmalink.
All data are stored on the server, client only uses server data.
2.1.1 Sigmalink Architecture: Communication
Sigma
Client
HTTP HTTP
Sigma
Client
Filesystem
File system can be used to share:
PCB scan (cf. §5.9)
Published Sigmalink program (cf. §0)
Directories can be configured using start-up parameters (cf. §2.4).
For performance reasons, it’s better to install Sigmalink on 64bits Operating System. In this
case, Sigmalink server will be able to assign more memory and then provide better
performances (PCB stitching,…)
Inline review is a little bit particular: it can be accessed only from local computer. But globally
follow the same architecture.

2.2 Manage license
Your Sigmalink server needs a license to start. This license is delivered by VIT support. If you don’t have
the license file or if you want a trial license, please contact your reseller or the VIT support team.
The licence file must be named exactly “sigmalink.licence”.
The license is only installed on the server. Client doesn’t require a license.
The license provides access to modules. For each module you have a maximum of simultaneous users
connected. If too many clients try to connect an error message is displayed. Contact your reseller if
you want to buy more token. There is no limit of declared users.
By default, you have access to “Configuration” and “Data import” modules. All other modules are
optional (cf. 2.8 to check your license).
Your license is specific to one server only. You must provide the MAC Address of your server. If you
don’t know how to retrieve your MAC Address, simply start your server (cf §2.3). An error message will
be displayed and a file named “server.def” will be generated. Then send this file to your reseller or to
VIT support team.
If you change your license file, you must restart your server to take in account this update.

2.3 Start server
Sigmalink server can be started in two ways:
In command line
By a windows service
Command line:
The first way is the best one at first installation and while you don’t have the final license.
Go to installation directory and double click on the file named start_server.bat.
You can find a shortcut in the windows menu : VIT Sigmalink > Sigmalink Web Server
In this mode, start-up logs are displayed.
Sigmalink tries automatically to assign the maximum available RAM memory to the server.
If you want to limit the memory assigned to Sigmalink or if you have the error message
“Could not reserve enough space for object heap”, edit start_server.bat and update the
lines
SET MAX_HEAP_SIZE=8192 on 64bits server
SET MAX_HEAP_SIZE_32=1536 on 32bits server
With Mo values.
E.g. SET MAX_HEAP_SIZE=1024, set memory to 1Go of RAM on 64bits OS.
Windows scheduled task:
The second way is to install Sigmalink Server as a windows scheduled task.
Sigmalink server uses at least, 1Go of memory. Install it as a service only if the machine is
dedicated to Sigmalink only or if you’re sure to always have enough memory available.
Go to installation directory and sub directory “tools” (Default is c:\VIT_Sigmalink\tools). Then double
click on the script called “install_http_scheduled_task.bat”.
On Windows 7, you must be administrator to install Sigmalink server as a scheduled task.
To avoid the security confirmation popup, you can launch this script as administrator.
If this operation succeeds, you will find a new windows scheduled task:

2.9 Logs and dumps
Sigmalink server creates two kinds of technical information to help support in case of problem:
Log files: automatically created by the application and the http server. Files are created in
C:\VIT_Sigmalink\logs.

contains last technical logs, last functional logs, and some contextual information. Dumps are
created in c:\VIT_Sigmalink\data\dumps.
You can change the log level (cf: §2.4)

3.1.3 Logout
Logout is very important to release license token. Due to license, some modules can have limited
concurrent accesses. When you logout, the token is released then another user can use it to connect.
If you close the Sigmalink client or your web browser without logout, the token is not released. Your
token will be released only after expiration (1 hour).
The logout button is available at bottom right of the screen. A confirmation message asks you to check
if all your data have been saved before to logout.
3.1.4 Session duration
You’re connected to the Sigmalink server by a session. Session is automatically closed if no interaction
with the server (e.g. save, load,...) has been done during 30 minutes.
When your session has expired, system asks you to login again.
Enter your password (login is kept in memory) and click “Login”.
The action you’ve asked is aborted. After identification, you’ll have to re do your action.
Data you’re using (like program) are stored locally in the client memory, and then even if
your session expired, nothing can be lost.

6.1.2 Installation
Sigma Review can be used in different context:
- Embedded Review
- Inline Review
- Dual lane inline review
- Offline Review
For each of this context, a different installation and configuration will be required.
Embedded Review
The Embedded Review is not commonly used because it blocks the inspection process of next panel,
and this could be problematic in post reflow.
It requires an Inline Review installation, onto the K machine computer, where Vision software is
running. The client can be launch on this same computer, on a separated screen, or on another
computer, beside the machine.
Inline Review
The Inline Review is used for single lane K machine, with a downstream single stacker conveyor (VIT
Vi200, Vi220). The Inline Review is connected to the conveyor through an IO board.
It requires an Inline Review installation, onto the computer connected to the conveyor with an IO
board. The client can be launch on this same computer.
Dual-lane Inline Review
The Dual-lane Inline Review is used for dual lane K machine, with double downstream single stacker
conveyor (VIT Vi24x). The Sigma Review is connected to the conveyor through an IO board.
It requires a Sigmalink Server installation. The clients must be launched onto each computer connected
to each conveyor lane with an IO board.
Offline Review
The offline review can be used for any kind of CI equipment.
It requires a Sigmalink Server installation. The client can be launch from anywhere.
Inline and offline review must be installed separately on different machines. The same
installer is used with different options. Please use installation guide for full information.
Please check §2 of this manual for administration guide and §3 for common behavior like
first connection.

Sanctions
System provides two kinds of action to give a sanction to a defect.
“False call”. Current defect is acceptable.
“True call”. Current defect is not acceptable.
“Repaired”: The current defect has been repaired
Even if labels and codes are fully configurable(see Custom Actions), ViTechnology provides default
action for each sanction:
False Call:
Acceptable. Operator analyze that something is wrong but take the risk to ignore this defect.
False call. Inspection system make a mistake: current component have no problem. Ideally,
inspection system programmer must tune is model to avoid this kind of defect.
Panel acceptable: all the defect of the entire panel are set as acceptable.
